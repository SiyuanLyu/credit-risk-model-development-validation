# Credit Risk Model Development & Independent Validation
### PD / LGD / EAD · CECL-style loss forecasting · CCAR-style stress testing · SR 11-7 validation

An end-to-end retail credit-risk modelling project built on the public UCI
credit-card dataset (30,000 accounts), structured the way a bank model-risk
team would organise the work: a development document, an independently
written validation report, and a fully reproducible pipeline.

## Structure
```
src/
  01_data_prep.py     cleaning, feature engineering, train/test split
  02_pd_model.py      WOE/IV scorecard (champion) vs. XGBoost (challenger)
  03_lgd_ead.py       EAD (CCF), LGD scenarios, portfolio expected loss
  04_validation.py    SR 11-7 outcomes analysis: discrimination,
                      calibration, PSI stability, benchmarking
  05_cecl_stress.py   macro satellite overlay, 3 supervisory-style scenarios
docs/
  Model_Development_Document.md
  Independent_Validation_Report.md
outputs/              metrics, calibration tables, ROC / KS / calibration plots
data/raw/             UCI dataset + FRED macro series (UNRATE, GDP, HPI, PAYEMS)
```

## Quick start
```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python src/00_download_data.py   # data is downloaded, not committed
bash run_pipeline.sh
```
Baseline results: see `outputs/baseline_results.md`
(champion AUC 0.759 / KS 0.404; challenger AUC 0.780; PSI 0.002).

## Automation (GitHub Actions)
- **model-pipeline** (on every push): re-runs the full pipeline and acts as a
  validation gate — the build fails if the champion's test AUC falls below 0.70.
- **ongoing-monitoring** (weekly): draws a fresh simulated production batch,
  computes PSI vs. the development sample (`src/06_ongoing_monitoring.py`),
  and opens an issue automatically on a PSI breach (> 0.25). One week in four
  uses a drifted batch, and the monitor does catch it (PSI ≈ 0.37 in testing).
- **build-docs** (on docs changes): renders the development document and the
  validation report to PDF with pandoc.
- Data files and prediction CSVs are git-ignored and regenerated by the
  pipeline; metrics, plots and reports in `outputs/` are committed as evidence.

## Data
- Yeh & Lien (2009), UCI ML Repository #350 — credit-card accounts with
  6 months of repayment behaviour; target = default next month.
- Macro scenarios: FRED (UNRATE, GDPC1, CSUSHPISA, PAYEMS).

## ML extension (Steps 7–8, optional dependencies)
- `07_sequence_model.py` — GRU sequence model (PyTorch) on the raw 6-month
  behavioural sequence as challenger #2: test AUC 0.764.
- `08_explainability.py` — governance pack for the ML models: monotonicity-
  constrained XGBoost (AUC 0.765 vs. 0.780 unconstrained — the measurable
  price of directional sanity), SHAP global importance, and ECOA-style
  adverse-action reason codes for the highest-risk accounts.
- Findings and the four-way model comparison: `outputs/ml_extension_results.md`.
- Install with `pip install -r requirements-ml.txt`, run `bash run_ml_extension.sh`
  (core pipeline must have run first). Kept out of the default CI so the
  validation gate stays fast.
